# Decision Log

| Date | Decision | Alternatives considered | Rationale |
|------|----------|------------------------|-----------|
| 2026-11-08 | Chose NestJS over Express | Express, Fastify | Rubric requires visible module boundaries; NestJS enforces them via `@Module()` decorator system |
| 2026-11-09 | Chose PostgreSQL over MongoDB | MongoDB | Relational queries suit leaderboards; joins connect runs to users and games |
| 2026-11-09 | Chose Prisma over TypeORM | TypeORM | Type safety and migration ergonomics |
| 2026-11-09 | Pinned Prisma to 5.22 | Prisma 8.0.0-rc.33 (scaffold default) | Stable release instead of a release candidate; keeps the classic `url = env(...)` datasource |
| 2026-11-09 | Refresh token rotation, stored as SHA-256 hashes | Stateless refresh JWTs, server-side session store, bcrypt-hashed tokens | Revocation without a session store. SHA-256 is deterministic so the `@unique` column can be looked up; bcrypt salts each hash and truncates input at 72 bytes, which is unsuitable for long JWTs |
| 2026-11-09 | Kept NestJS 12 and Vitest from the scaffold | Downgrade to NestJS 10 and Jest as first planned | The installed versions work and are maintained; downgrading adds risk without changing the module architecture |
| 2026-11-09 | JWT access tokens instead of server sessions | Session store in Redis | Requests are verified from the signature with no lookup; the database-backed refresh token still allows revocation |
| 2026-11-09 | HttpOnly SameSite=Strict cookies instead of localStorage | localStorage with a Bearer header | Browser JavaScript cannot read the tokens, which limits XSS theft; SameSite=Strict stops them being sent cross-site |
| 2026-11-09 | Retry Fish API 3 times with exponential backoff (300, 900, 2700 ms) on network errors and 5xx only | No retries; fixed-delay retries; retrying every error | Rides out brief outages without hammering the server; 4xx and malformed responses will not improve on retry, so they fail immediately |
| 2026-11-09 | `FISH_API_URL` is the base `https://marcconrad.com/uob` | Full `/fish/api.php` URL as first planned | Each category has its own path. Testing showed the full URL plus a category path still returns 200 with a fish puzzle, silently serving the wrong category |
| 2026-11-09 | Redis cache-aside for games (5 min) and leaderboards (30 s, cleared on each new run) | No cache; in-memory cache | Leaderboards are read far more often than written; Redis is shared across backend instances. Cache errors fall back to the database so Redis is never a single point of failure |
| 2026-11-09 | Leaderboard ranks best run per game, total points across all games | Every run as its own row | Matches the prototype and stops one player filling the board |
| 2026-11-09 | Socket.IO for gameplay, SSE for the leaderboard | Polling; WebSockets for everything | Socket.IO gives bidirectional messaging and reconnection. SSE is simpler for a one-way feed. Polling wastes battery and adds latency |
| 2026-11-09 | Emit `run.created` from `RunsService`, not the gateway | Emit only in the WebSocket handler as first planned | Games save runs over REST, so a gateway-only event would never fire during real play. One emit point covers both routes |
| 2026-11-09 | Authenticate sockets in Socket.IO middleware and recheck token expiry on `game:submit` | Authenticate only once on connect | Invalid tokens never get a connection, and a long-lived socket cannot outlast its 15-minute token |
| 2026-11-11 | Zustand stores for auth and live game state; `AuthProvider` only boots the session | React Context for all state | Any component reads a slice without prop drilling or re-rendering the whole tree; the socket writes to `gameStore` and components only read |
| 2026-11-11 | One shared in-flight `/auth/refresh` for concurrent 401s | Each failing request refreshes on its own | Refresh tokens rotate and work once, so parallel refreshes would log the user out |
| 2026-11-11 | Game presentation (colour, rules text) in `frontend/src/games/registry.ts`; database `Game` rows for integrity | Render the dashboard from `GET /games` | Colours and help text are UI concerns; the seed mirrors the same slugs, names and emojis |
| 2026-11-11 | Prototype CSS placed in Tailwind `@layer base` and `components` | Paste it as plain CSS | Unlayered CSS beats Tailwind utilities, which forced `!important` in the prototype; layers let utilities override cleanly |
| 2026-11-11 | Renamed the slice game "Fruit Slash" (slug `fruit-ninja` kept) | Keep "Fruit Ninja" | Avoids using an existing commercial game's name; the slug stays so the agreed API and seed are unchanged |
| 2026-11-11 | Every action game split into pure `engine.ts`, read-only `renderer.ts` and thin React glue, on a shared `BaseEngine` | Port the prototype's single global `G` object and functions as they are | Engines have no React or DOM and can be reasoned about alone; shared rules (combo, lives, countdown, particles) live once. Engines queue sound cues instead of calling WebAudio |
| 2026-11-11 | Engines use their own game clock (`state.time`) rather than `performance.now()` | Wall-clock time as in the prototype | Timers such as Snake's 7-second bonus food no longer run out while the game is paused |
| 2026-11-11 | Action games read hidden answers through an `AnswerSource` interface fed by `AnswerQueue` (backend `/fish/puzzle`, random digit if it fails) | Engines call the API themselves | Keeps HTTP out of the engines, keeps two answers buffered so play never waits, and the game stays playable if the Fish API is down |
| 2026-11-11 | Fish Count: shared `PuzzleEngine` with `{ lives: 3 }` | Its own engine copy | The four puzzle games differ only in rules, so one engine plus a rules object per game avoids four near-identical files |
| 2026-11-11 | Banana Streak: `PuzzleEngine` with `{ streak: true }` (x1 to x5 multiplier) | — | Same engine; the multiplier rule is one line in `answer()` |
| 2026-11-11 | Tomato Rush: `PuzzleEngine` with `{ timeLimit: 60 }`, ticked by a 1-second interval in the React layer | Timer inside the engine | The engine stays free of timers; React owns the interval and calls `tick()` |
| 2026-11-11 | Smile Cove: `PuzzleEngine` with `{ rounds: 10, hintCost: 3 }` | — | Hints are an engine method (`takeHint`) so the cost is applied in one place |
| 2026-11-11 | Snake: `SnakeEngine` with queued turns (max 3) and keyboard, swipe and D-pad all calling `turn()` | Separate handlers changing direction directly | One entry point blocks reversing into yourself regardless of input device |
| 2026-11-11 | Fruit Slash: `FruitSlashEngine` with segment-to-circle slice detection on pointer events | Hit-testing only the pointer position | Fast swipes skip over fruit between frames; testing the whole segment matches the prototype's feel |
| 2026-11-11 | Star Scraper: `StarScraperEngine`; the ship sprite is loaded by React and passed to the renderer | Renderer creates its own `Image` | The renderer only draws; loading assets is a browser concern for the React layer |
| 2026-11-12 | `GET /health` returns 503 only when the database is down; Redis or Fish API failures report "degraded" | Fail on any dependency | The app has working fallbacks for Redis and the Fish API, so only a database outage stops players |
| 2026-11-12 | Multi-stage backend image running as the non-root `node` user, migrations applied at start; nginx image for the frontend; both behind an optional compose `app` profile | Single-stage image running as root; always containerise the app | A smaller image without build tools, least privilege, and day-to-day development stays fast with `npm run dev` |
| 2026-11-12 | Backend tests in Vitest with Supertest; fakes replace the database and HTTP client | Jest; tests against a real database | Vitest came with the scaffold and runs Nest's dependency injection; fakes let `npm test` pass without Docker |
| 2026-11-11 | Runs saved through `POST /games/:slug/runs` when a game ends or is exited after at least one attempt | localStorage as in the prototype; WebSocket `game:submit` | REST gives a clear success or failure with a retry button; the backend still broadcasts the run to every player |
